# 碳核算台账标准化（Carbon Ledger Standardizer）

面向企业碳核算数据工程师的网页工具，包含两个页面：

1. **台账标准化**：上传**字段合同 JSON** 与各厂区**能源台账 CSV**，
   在浏览器中查看字段映射、歧义与错误行；仅当台账完全合格时，才提供标准列 CSV 下载。
2. **表计核对**（`/meters`）：上传标准列读数 CSV 与单根表计树 CSV，
   枚举能完整覆盖末端点位、又不重复计量的所有表计组合，给出最小/最大用电量；
   两值不同即标记为待核查，缺读数的分支直接指出且不给总量。

## 快速启动（Docker Compose）

```bash
docker compose up --build -d
```

打开浏览器访问 <http://localhost:8000>（健康检查：`/healthz`）。
停止：`docker compose down`。

容器以非 root 用户运行，根文件系统只读，仅开放 8000 端口。

## 本地开发（不使用 Docker）

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
python3 -m pytest -q
```

## 字段合同格式

```json
{
  "fields": [
    {"name": "厂区",        "aliases": ["工厂", "site"], "type": "text",    "required": true},
    {"name": "月份",        "aliases": ["统计月份"],      "type": "month",   "required": true},
    {"name": "用电量(kWh)", "aliases": ["电量", "kwh"],   "type": "decimal", "required": true},
    {"name": "抄表次数",    "aliases": ["次数"],          "type": "integer", "required": false}
  ]
}
```

* `type` 仅限 `text`（文本）、`integer`（整数）、`decimal`（有限小数）、`month`（`YYYY-MM`）。
  也接受中文写法「文本 / 整数 / 有限小数 / 月份」。
* `name` 本身即可作为来源表头，别名无需重复标准列名。
* 表头匹配忽略大小写、全/半角宽度差异与多余空白（`Energy (kWh)` ≡ `energy（kwh）`）。
* 示例文件见 `samples/contract.json`、`samples/ledger.csv`。

## 校验与映射规则

| 场景 | 行为 |
| --- | --- |
| 源列命中别名 | 必须**一一对应**到唯一标准列 |
| 必填标准列无来源 | 拒绝，列出缺失列 |
| 存在多种完整映射 | 拒绝，列出全部候选方案（不按列顺序、票数或样例值猜测） |
| 重复表头（含规范化后重复） | 拒绝，整体不处理 |
| 必填单元格为空 | 拒绝，定位到行号/列 |
| 任一数据行列数不符 | 拒绝，定位到行号 |
| 任一数据行类型不符 | 拒绝，定位到行号/列/值 |
| 未命中别名的额外列 | 忽略，不进入结果 |
| 数据行整行留空（`,,`） | 视为数据行，必填列报空；真正的空白行忽略 |

所有校验为**全有或全无**：只要存在上述任一问题，就不生成任何部分结果或下载链接。

类型语法（严格、整串匹配，不做隐式修剪之外的转换）：

* `integer`：`[+-]?[0-9]+`，例如 `0`, `-12`, `+5`
* `decimal`：`[+-]?([0-9]+(\.[0-9]+)?|\.[0-9]+)`，不接受 `NaN`/`inf`/科学计数法/千分位逗号
* `month`：`YYYY-MM`，月份 `01`–`12`
* `text`：任意字符串（必填时空值视为错误）

映射由约束求解枚举得出：每个命中别名的源列必须分配且只分配一个标准列，每个必填标准列
必须被覆盖；若满足条件的完整分配不唯一（或候选过多无法证明唯一），一律拒绝并列出候选方案。


## 表计核对（/meters）

核对厂区月度购电量时，总表与分表同时入账会重复计量。本页用表计树把“不重复且全覆盖”的
口径问题转化为树的**切割面（frontier）**枚举。

### 输入文件

**读数 CSV**（工具导出的标准列，UTF-8）：

| 标准列 | 接受的别名（节选） | 说明 |
| --- | --- | --- |
| 厂区 | 工厂、厂站、site | 文本 |
| 月份 | 统计月份、年月、period | `YYYY-MM` |
| 计量点 | 表计、meter | 须与表计树中的名称一致 |
| 用电量 | 用电量(kWh)、电量、kwh、electricity_kwh | 非负有限小数 |

**表计树 CSV**（单个厂区、单根，UTF-8）：`计量点,上级计量点` 两列，根表的上级留空；
单个厂区最多 200 个点位。表头匹配同样忽略大小写、全/半角宽度与多余空白，
未命中的额外列忽略并提示。示例文件见 `samples/meter_readings.csv`、`samples/meter_tree.csv`。

### 核对规则

* 父表读数可代表整棵子树，也可分别采用子表读数；**祖先与后代绝不同时计入**。
* 合法组合是覆盖全部末端点位的切割面：每个末端恰被一个选中表计的子树包含。
* 树 DP 枚举所有合法组合（链状 200 点也只需线性时间），输出：
  * **最小、最大用电量**及各自采用的表计；两值不同即标为 **待核查**。
  * 组合总数；本期每条读数是否进入最小/最大组合；本期无读数的表计清单。
* 若不存在完整组合（某条分支完全没有读数），列出**无法补足的分支**
  （自根表的路径与涉及的末端点位），**不给任何总量**。

### 报错即拒绝（不给总量）

| 场景 | 行为 |
| --- | --- |
| 同一厂区/月份/计量点重复读数 | 拒绝，定位两次出现的行号 |
| 负数用电量、非有限小数（NaN/inf/科学计数法等） | 拒绝，定位行号 |
| 月份不是 `YYYY-MM`、必填单元格为空、行/列数不符 | 拒绝，定位行号 |
| 表头缺失必填标准列或一列命中多个标准列、重复表头 | 拒绝 |
| 选中范围内出现表计树之外的计量点 | 拒绝，列出未知表计 |
| 多根表、无根表、上级未定义、自指、环路、计量点重名、空名称 | 拒绝 |
| 表计树超过 200 个点位 | 拒绝 |

读数文件为全文件校验：任一行存在上述问题，整个文件都不会进入厂区/月份选择步骤。

### 操作流程

1. 打开 `/meters`，上传读数 CSV 与表计树 CSV。
2. 校验通过后，从下拉框选择**厂区**与**月份**（选项来自文件实际内容）。
3. 查看最小/最大组合、待核查标记或缺失分支；解析结果在服务器内存中保留 30 分钟，
   可在同一页切换厂区/月份重新计算。


## 上传限制

* 单文件 ≤ 10 MiB；台账须为 UTF-8（可带 BOM）。
* 结果保存在服务器内存中，下载链接 30 分钟有效；重启即失效。
* 输出的标准列 CSV 为 UTF-8 带 BOM（便于 Excel 正确识别中文表头）。

## 项目结构

```
app/
  main.py       FastAPI 路由、上传处理、内存下载/会话存储
  spec.py       字段合同解析与规范化
  engine.py     映射枚举、歧义检测、逐行类型校验、结果生成
  reconcile.py  表计树校验、读数校验、frontier 树 DP 与缺失分支定位
  templates/    浏览器页面（含表计核对三页）
  static/       样式
tests/          pytest（引擎规则 + HTTP 端到端）
samples/        可直接上传的示例（含 meter_readings.csv、meter_tree.csv）
```
